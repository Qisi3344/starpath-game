# 《星途计划》讨论决议 ↔ GitHub 文档 ↔ 代码落地对账

审计时间：2026-10-12。检查范围：`main`、PR #4 (`ui/m1-shell`)、V1.6.2 原始制作包，以及已确认的 ADR-0001～0005。**这是现状核查，不是功能完成证明。**

## 看状态时区分三个层次

- **归档**：决议/原始策划进入仓库，但不代表功能可玩。
- **UI/类型**：页面能打开或数据类型已建立，但不代表业务规则运行。
- **闭环可玩**：玩家行动真正改变唯一世界状态，并与时间、员工、财务、剧情、存档相连且经过测试。

当前 `main` 只有早期第一周 React 骨架和原型；以下“部分实现”一般指 **PR #4 未合并代码**。CI 成功仅说明当前测试与构建通过，不等于画面、行为或长期数值平衡均已验证。

## B. Alpha 第一个游戏月（P0：缺失的真正经营）

- [ ] 唯一游戏日期与时间推进（第一周线性脚本扩到可安排的整个月）；跨周/月结算。
- [ ] 艺人多天训练、培养与通告占用同一档期；疲劳、金钱、工作容量校验，冲突明确提示。
- [ ] 员工委派工作引擎：预算、预计完成日、员工能力/容量、进度和真实产物；日常无需老板反复点击。
- [ ] 招募完整闭环：寻找→天数→汇报→查看候选→约谈/报价→接受或拒绝→老板批准→入职名单；无候选与竞争对手抢签。
- [ ] 地图真实可做的探索/外派动作：地图资源可在手机、通告和日程中共享单一任务 ID。
- [ ] 艺人列表/详情、成长路线、档案、履历与签约状态的实际数据；不能硬编码展示。
- [ ] 通告市场、匹配要求、竞标/签约、录制工期、费用、净收益、作品/曝光反馈及结算幂等。
- [ ] 手机由实际事件生成消息、热搜和审批提醒，消息能跳转到唯一的真实事项。
- [ ] 剧情和经营双向影响：比如公关、合同、通告选择改变后续事件池，不只是文本。
- [ ] 本地版本化存读档，读取后剧情/任务/地图/候选/财务状态一致。
- [ ] 移动端触控、返回链、文字缩放、安全区与完整首月流程浏览器验收。

## D. 文档/实现不一致或易引起误会（应整理）

1. ADR-0001 的“C 尚未最终选择”、ADR-0004 的“导航尚待确定”属于**历史性措辞**，以更新的 ADR-0004（C 已选）和 ADR-0005（导航已定）为准，后续整理时可删除或显著标为过时。
2. `src/game/types.ts` 已给出了多种对象类型，但第一周 `src/game/engine.mjs` 没实现其状态流转，**类型存在 ≠ 功能存在**。
3. `src/game/industry-districts.ts` 记录了部分 `locked/preview`，当前地图入口并未按状态完全约束点击。需要在行为上线时统一可访问性和解锁条件。
4. `ProfilePage` 里存读档是明确的“建设中”；刷新失去内存状态，不可把当前 PR 宣称为“可完整存档试玩”。
5. C 视觉仅初步 token 化，实际画面仍使用原型矢量背景/卡片，不能以构建成功作为视觉验收。
6. 当前 PR #4 未合并至 `main`。运行主分支体验到的仍是较早的骨架。

## E. 推荐优先顺序（防止又陷入反复堆策划）

1. **先补资源与准绳**：C 六屏原图入库，消除过期文档措辞；不新增其他主题/导航备选。
2. **完成自由游戏日与存档的共享世界状态**（后续系统依赖它）。
3. **做员工委派→招募报告→老板审批这条独特玩法链**，并通过手机/地图跨页面验证。
4. **做培养/档期冲突→通告执行→作品履历→结算**，形成首个完整游戏月。
5. **基于实际手机浏览器验收 C 方案 UI**，再择机合并 PR #4。
6. **扩长期内容**：部门升级、同行竞争、选秀、反向挖角、羁绊和复仇终局，不要早于首月可靠可玩。
