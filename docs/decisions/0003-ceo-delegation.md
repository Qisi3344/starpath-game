# ADR-0003 · 玩家是老板：决策层与员工执行层

**状态：核心原则已确认；具体工期、概率、费用等待试玩调优。**

## 定位与理由

玩家是重返娱乐圈、创建独立经纪公司的**老板/负责人**，不是必须亲自处理全部杂务的唯一经纪人。《星途计划》采用**老板下达战略意图、员工持续执行、过程汇报、玩家决定关键结果**的“委派—反馈”框架，并与已确定的 Galgame 叙事、深度经营系统共享状态。

此决议承接 V1.6.2 原案已有的星探挖掘、选秀签约、同行挖角、自荐上门四条途径，以及经纪部、星探部、法务部、手机经纪人汇报；**不是推翻原规则或追加一套重复的艺人签约系统**。

## 玩家 / 员工职责边界

| 事务 | 老板（玩家） | 员工（后台主动执行） |
| --- | --- | --- |
| 招募艺人 | 决定方向、预算、重点目标、最终签约及合同授权 | 搜寻、初筛、建立联系、核查基础背景、提出候选方案、初步谈判 |
| 艺人培养 | 定职业方向、阶段目标、预算、重要机会优先级 | 执行训练计划、提醒疲劳/档期冲突、推荐调整 |
| 商务通告 | 批准重点合作、定报价底线、分配艺人、取舍风险 | 寻找机会、对接平台、准备资料、跟进时间线 |
| 公关 | 选择公开立场、批准重大支出、承担后果 | 监测舆情、整理备选方案、在授权范围内例行处理 |
| 日常管理 | 制定运营策略、招聘核心人才、批准投资与重大合同 | 发通知、同步状态、整理报表、排除普通协调问题 |

**权限红线**：员工未经玩家授权，不得自动签约、擅自支付高额违约金、永久出售关键权益、替玩家做复仇主线选择或重大公关表态。例行小额事项可在玩家事先设定的预算与策略内自动处理。

## 新艺人招募：老板视角工作流

1. **玩家发起意向**：「艺人招募 / 发掘新人」→ 选择方向（偶像/演员/综艺/不限）→ 搜寻渠道、预算与目标偏好 → 派给负责人。
2. **后台推进**：任务占据员工/部门对应的工作容量，随游戏日历推进；员工会在日常汇总中反馈进度，无须逐日反复点击。
3. **阶段性消息**：可能提示正在接触、资料不足、某候选人已有其他公司接洽、是否追加调查费等；只把需要决策的事情升级为玩家待办。
4. **交付推荐名单**：一般返回 2–4 名**尚未与本公司签约**的可接洽候选人；可能因资源不足或市场竞争而无人合适，不能强制每轮出天才。
5. **老板筛选**：查看职业方向、当前能力、潜力可信度、期望合同、个性/风险、关系与时效；可选择继续观察、安排试镜、提出报价、暂不签。
6. **谈判与签约**：经纪人按授权区间先行沟通；超出预算、艺人拒绝、对手截胡、条款冲突等需要玩家选择。**只有谈判达成并确认合同，艺人才进入旗下名单**。
7. **后续衔接**：签约进入艺人档案、职业规划、排期与履历。没签的人可保留在候选档案中直至失联/签约别人/逾期。

### 首月建议参数（仅供原型试跑）

- 一次搜寻约 **3–7 游戏日**；初期 **2–4 份资料**，具体结果依人才池、地区、人脉、预算与随机种子决定，并允许找不到合适人。
- 可视的“预计完成日”“剩余天数”“负责人”“使用预算”“目标方向”；时间随着已有日历流逝，不能额外开一个与主日历分离的计时器。
- 运营小型工作室时，**林知夏暂时兼做初步寻访与联系人整理**；星探部建设后把规模化搜寻交给专职人员。
- 初次主线签约陆星遥是**剧情特殊入口**，不能被普通搜寻任务替换；第 2 个月沈亦辰加盟同理保留剧情入口。
- 不强制玩家每次挑选所有条件；保留「按经营方针自动初筛」的简化派遣入口。

以上数值都是**可配置草案**，需由首月玩法验证，不应在 React 组件中硬编码。

## 员工必须主动工作，但不能接管老板身份

- 即使玩家没有每次手动派单，员工也按职责持续产生合理工作成果（新的通告线索、舆论日报、档期预警、潜在人才情报、合同到期提醒）。
- 这类工作是**真实可溯源的任务/信息生成**，不是空洞重复文案；员工能力、所在部门、人脉、任务占用与市场状态决定成果。
- 重要汇报使用手机消息、面对面 Galgame 对话或办公待办；常规汇报合并为摘要，避免每日刷屏。
- 可区别「建议」「需要审批」「完成/失败」「突发危机」消息等级；仅真正需要选择的消息中断时间推进。
- 玩家可以直接介入少量高价值场景：特殊艺人面谈、关键选角、重要公关谈判。亲自介入是**策略选项**，不能成为每单必跑的强制重复动作。

## 初次见面的剧情范例（非最终台词）

林知夏：「我让人联系了几位目前没有签经纪公司的新人，有三份资料值得你看看。」

老板可以：① 安排试镜 ② 让林知夏先谈合同底线 ③ 全部暂缓 ④ 调整条件继续找。

与其设计一个“艺人商店”，更应让玩家觉得有一支团队在替自己做事。

## 与旧系统关系

- 沿用四种原始招募渠道；本文定义“由谁执行、如何等待、如何汇报、何时需要老板审批”。
- 经纪部与星探部沿用 V1.6.2；员工系统坚持轻量化，**不引入繁琐招聘考勤、绩效、薪资明细微管理**。
- 保留人员个性与职业履历，但不要让部门/员工拥有凭空无限产出或无限并行任务的能力。
- 将“签约玩家最后审批”作为保底规则；失败、违约、竞争均可触发剧情而非单纯扣分。

## 技术与验收

核心对象至少含：`RecruitmentTask(id, ownerId, channel, targetProfile, budget, startedAt, dueAt, status, seed)`、`Candidate(id, identity, currentStatus, contactStatus, profile, expectations, expiry)`、`Offer(candidateId, terms, status)`，具体类型可按架构归一化。

- 任务创建必须检查经纪人或部门容量及预算；同任务重复触发不应重复扣费。
- 时间前进推进任务，按固定种子生成结果；读档后不得重新抽取获奖般的候选人。
- 无候选人、候选人拒绝、竞争对手抢签、过期等分支都需成立。
- 候选人仅在`SIGNED`后加入所属艺人名单；员工不能绕开老板批准。
- 背景任务与主线剧情可以并行；大危机/对话中止时间推进时，任务进度不应偷偷增长。
- 首月 Alpha 至少跑通：下达一次搜寻 → 日历推进 → 资质报告 → 查看候选人 → 谈判/拒绝 → 状态更新/存档恢复。
