# 艺人培养、职业履历和涌现式故事 · 设计草案

**状态：玩法方向已认可，系统参数与最终数据模型未锁定。** 本文件是开发参考而非强行新增的完整功能清单；优先 M1 的月度闭环。

## 体验目标

玩家培养的不是一串能力数值，而是有背景、性格、愿望、作品和成长史的艺人。老板的选择应创造可记住的作品、机遇、挫折、关系和行业地位。

**大循环**：发掘与签约 → 规划与培养 → 竞争与通告 → 作品与曝光 → 舆情与危机 → 结算与职业成长 → 新一轮资源机会。

## 发展路线不是职业枷锁

可选倾向：**偶像**（舞台、选秀、专辑、巡演）、**演员**（试镜、作品、演技、奖项）、**综艺**（真人秀、综艺感、路人缘、常驻机会）、**多栖发展**（跨领域、更复杂的资源取舍）。

- 玩家决定主要发展路线；路线可按作品与契机转变，不设不可逆的职业硬锁。
- 训练只是影响机会的一部分；作品匹配、人脉、市场行情、疲劳、宣传、公关和竞争均重要。
- 艺人会有偏好与自己的建议，不始终被动接受；是否违背其意愿需体现成本与后续关系变化。
- 训练、作品与通告应竞争同一档期资源；不能一天无限训练又无限拍片。

## 作品履历：让过去改变未来

每个影视剧、综艺、歌曲、舞台/代言项目应有身份与结果，形成长期作品履历：

- `ProjectRecord` 建议包含：类型、名称、角色/番位、期间、成本与收益、口碑、曝光、角色适配与后续人脉/行业机会。
- 完成作品不仅提升人气、金钱，还能影响某类型试镜概率、行业评价、导演关系、粉丝结构与职业选择。
- 为可调整的工作记录和事件标签预留扩展；不要一次性堆砌二十种进度条。
- 剧情节点根据项目履历与玩家选择条件化触发，不是所有结局都预先写死。

## 人物故事来自经营

参考原有 V1.6.2 的人物事件库，采用两层：

1. **关键作者剧情**：陆星遥、沈亦辰、林知夏、星煌主线、关键羁绊等，有质量可控的故事节点和条件。
2. **经营涌现事件**：档期冲突、惊喜试镜、低预算作品意外爆红、艺人疲劳、对手抢人、粉丝反应等，来自可复现的世界状态与事件规则。

两者在同一世界状态中接续。例：新人争取女二试镜 → 临时加训或靠人脉面谈 → 录制期间档期冲突 → 上映口碑反馈 → 解锁特定导演下一部戏的邀请。不能只展示“人气 +5000”而不留下履历。

## 体验平衡原则

- 玩家作为老板批准发展方向、重大机会和预算；员工负责联系、安排、预警与常规执行，参见 ADR-0003。
- 避免卡牌抽取、纯经验材料升级、每天重复点小游戏等将人扁平化的设计。
- 在玩法策略可理解与信息不完全之间取得平衡：现有能力可以看见，潜力不必完全透视，但应有可信线索，不做不可推理的黑箱胜败。
- 艺人职业发展路线影响优先级，不保证“选择演员就自动成为演员顶流”。

## 分阶段落地

- **M1**：一名艺人 + 一个简单通告/小作品的履历记录 + 有后果的培养/排期/委派决策。
- **M2**：多艺人职业倾向、履历对新机会的影响、不同员工的专业分工。
- **M3**：大型选秀、音乐/影视长期路径、复杂羁绊、影响行业格局的公司竞争与复仇线。

不得把这里的构想直接当作已经写好的代码或已经测试过的玩法。
